# AI 能力边界

在决定某个行为归属于哪一层时，使用本指南。

| 层 | 拥有 | 不应拥有 |
| --- | --- | --- |
| 提示词（Prompt） | 模型指令、语气、推理格式、输出形态 | 授权、持久的业务事实、不可逆写入的批准 |
| 目录/配置 | 带版本号的业务边界、标签、示例、阈值、归属 | 复杂的命令式工作流或隐藏的副作用 |
| Agent/编排器 | 上下文加载、路由、编排、能力选择 | 编造业务事实或绕过下游控制 |
| 场景技能（Scenario Skill） | 一个完整的用户任务：槽位、阶段、Tool 权限、确认、降级、输出 | 绕过 Tool 契约的原始数据访问 |
| Tool/服务 | 原子读写、校验、授权、幂等性、业务事实 | 理解完整的对话目标 |
| 记忆/状态 | 结构化、有边界、有来源、有过期时间的状态 | 把摘要或旧的模型输出当作已核实的真相 |
| 评估器 | 证据、指标、发布门禁、失败归因 | 成为生产环境的决策者 |

## 选择能力层

按顺序询问：

1. 该行为是否属于安全、权限、校验或写入约束？把它放进 Tool/服务边界的确定性代码。
2. 是否是一个跨多个步骤或 Tool 的完整可复用用户任务？使用场景技能。
3. 是否在选择下一个运行哪个能力？交给 Agent/编排器。
4. 是否是一个频繁变更的业务分类、策略边界、示例集或阈值？使用带版本号的目录/配置资产。
5. 是否只是对模型表达或结构化生成的指引？使用提示词。
6. 是否必须跨轮次存活？只存储显式的或经 Tool 核实过的结构化状态，并带来源、边界、置信度与过期时间。

## 警示信号

- 某个 Tool 被改名为"Skill"，却没有槽位、阶段、降级、版本或评估。
- 修改提示词需要在多处修改代码分支、权限与测试。
- Agent 可以在没有第二次确定性确认检查的情况下调用写入 API。
- 一次成功的 API 调用被计为已解决的用户任务，却不检查业务结果。
- 记忆摘要可以静默覆盖当前轮次的显式输入。
