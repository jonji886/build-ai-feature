# 文档与交付门禁

## 每个关注点只保留一个事实来源

| 关注点 | 首选来源 |
| --- | --- |
| 范围与验收 | SPEC 或等价的需求文档 |
| 系统职责与数据流 | 架构/方案设计 |
| 长期存在的选择与权衡 | ADR |
| 外部输入/输出与错误 | API 或 Tool 契约 |
| 用法、价值、证据、限制 | README |
| 可执行的质量结果 | 由代码生成的评估 JSON/报告 |

不要将同一份人工维护的指标复制到多个文件中。从一个可执行结果中生成或渲染它。

## 为未来的评审者记录决策

对每个重要的 AI 决策，回答：

1. 是什么用户或业务问题需要该决策？
2. 考虑过哪些备选方案？
3. 为什么选择这个方案？
4. 如果缺少该能力会发生什么？
5. 该决策引入了什么新的成本或复杂度？
6. 哪些测试或指标能证明预期的价值？
7. 当前证据还不能证明什么？

## 交付清单

- 需求与验收标准与实现一致。
- 架构与契约与实际控制流一致。
- 高风险不变量有负面路径测试。
- 评估数据与报告与当前版本一致。
- README 说明价值、决策、权衡、证据与限制。
- 最终交接列出实际运行的命令；跳过的检查必须明确说明。
